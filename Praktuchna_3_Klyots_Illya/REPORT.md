1.	Що таке незмінність рядків (immutability) у C#? Які проблеми це створює і як їх вирішує StringBuilder?
Рядки в C# є незмінними об'єктами. Це означає, що після створення об'єкта string у пам'яті, будь-яка операція над ним (конкатенація, видалення символів) не змінює старий об'єкт, а створює абсолютно новий.

Проблеми: При багаторазовому об'єднанні рядків у циклах створюється величезна кількість тимчасових копій, що призводить до фрагментації пам'яті та сповільнення роботи програми через перевантаження збирача сміття (Garbage Collector).

Рішення: StringBuilder вирішує цю проблему, використовуючи внутрішній буфер (масив символів), який можна змінювати напряму. Це дозволяє додавати або видаляти текст без створення нових об'єктів у купі.

2.	У яких місцях програми ви застосували StringBuilder? Чому саме там, а не звичайну конкатенацію?
У моєму проєкті StringBuilder був застосований у наступних методах:

1)TextProcessor.BuildGroupReport: Для формування великого текстового звіту про всіх студентів групи. Використано замість конкатенації, бо кількість студентів може бути значною.

2)TextProcessor.GenerateCharacterization: Для генерації індивідуальних характеристик (Варіант 4), де текст збирається динамічно залежно від успішності студента.

3)AdvancedLogger.GetFullLog: Для накопичення та виводу системних повідомлень, що дозволяє уникнути гальмування при великій кількості логів.

3.	Наведіть результати порівняння продуктивності (ComparePerformance) для різних кількостей ітерацій.
За результатами роботи вбудованого тесту продуктивності (ComparePerformance):

1) При 1 000 ітераціях різниця між string та StringBuilder була мінімальною.

2) При 10 000 ітераціях StringBuilder показав результат у кілька мілісекунд, тоді як string почав помітно затримувати виконання.

3) При великих обсягах даних StringBuilder працює в десятки разів швидше.

4.	Які методи класу String використовувалися найбільше? Наведіть приклади з коду.
Найбільше використовувалися такі методи:

1) Split(';'): Використано в методі ImportStudentsFromText для розбиття текстового рядка на окремі поля студента (ПІБ, номер залікової).

2) Trim(): Для видалення випадкових пробілів на початку та в кінці введених даних.

3) IsNullOrEmpty(): Для перевірки наявності тексту в нотатках студента перед обробкою.

4) ToLower(): Для приведення тексту до єдиного регістру в алгоритмі перевірки паліндромів.

5.	Поясніть реалізацію методів IsPalindrome та Normalize.
Normalize: Очищує текст від зайвих пробілів та форматує його для збереження в базу.

IsPalindrome: Метод бере текст нотаток студента, видаляє пробіли та порівнює його з реверсованою копією. Використовується для аналізу вмісту поля Notes.

6.	Як ви інтегрували функціонал рядків у класи Student та StudentGroup?
1) У клас Student додано поле Notes (string) для зберігання текстової інформації.

2) У клас StudentGroup інтегровано методи ImportStudentsFromText (парсинг блоку тексту) та ExportToCsv (генерація CSV-рядка).

7.	Які труднощі виникали під час виконання роботи? Як їх вирішували?
1) Помилка CS0051 (несогласованность по доступности) при спробі передати internal клас StudentGroup у public метод.
Рішення: Зміна модифікаторів доступу на internal для методів обробки тексту, щоб вони відповідали рівню доступу моделей даних.

2) Помилка CS9035 через відсутність обов'язкових полів (required) при імпорті студентів.
Рішення: Додавання ініціалізації всіх обов'язкових властивостей (DateOfBirth, EnrollmentDate, PersonalEmail) безпосередньо в ініціалізатор об'єкта.

8.	Що нового ви дізналися під час виконання цієї практичної роботи?
Під час виконання роботи я навчився ефективно працювати з великими обсягами тексту, зрозумів різницю між типами string та StringBuilder з точки зору використання пам'яті, та опанував методи парсингу і форматування даних.
