Питання:



1. Що таке перевантаження операторів? Які оператори можна, а які не можна перевантажувати в C#? Перевантаження операторів дозволяє

визначити логіку стандартних символів для власних типів даних. Можна перевантажувати арифметику, порівняння, унарні знаки та логічні true і false. Заборонено перевантажувати присвоєння =, логічні зв’язки \&\&, || та спеціальні оператори типу typeof або is.



2\. Наведіть приклади перевантажених операторів з вашого коду (не менше 6 різних). У проєкті використано оператор + для злиття груп та об’єднання профілів студентів. Реалізовано знаки порівняння > та < для рейтингування. Додано унарний інкремент ++ та скалярне множення \* для векторів. Також впроваджено неявне приведення implicit та логічні оператори true і false для оцінок.



3\. Поясніть різницю між явним та неявним приведенням типів. Де ви їх використали? Неявне приведення виконується автоматично компілятором у безпечних ситуаціях, як у класі GradePoint при перетворенні числа на об’єкт оцінки. Явне приведення потребує вказівки типу в дужках через ризик втрати точності. Це застосовано у класі Vector для отримання довжини об’єкта як числа double.



4\. Для чого потрібні оператори true та false? Наведіть приклад використання. Ці оператори дають змогу перевіряти об’єкти в умовах if без додаткових методів. У моєму коді об’єкт оцінки повертає true, якщо бал вище восьми. Це дозволяє писати компактний код на кшталт if (currentGrade) для швидкої перевірки успішності студента.



5\. Як ви реалізували порівняння студентів? Які оператори для цього використовували? Порівняння реалізовано через оператори >, <, >=, <=, == та !=. Програма порівнює середні бали студентів, а при їх рівності звертається до показника навчального прогресу. Такий підхід забезпечує автоматичне та коректне сортування списку групи за успішністю.



6\. Які труднощі виникали при перевантаженні операторів? Як їх вирішували? Найбільшою складністю була обов’язкова парність операторів, що змушувало реалізовувати != разом із ==. Також виникали помилки при роботі з null посиланнями. Проблеми вирішено через ретельну перевірку об’єктів та використання сучасних операторів безпечного доступу.



7\. Як перевантаження операторів покращує читабельність коду? Воно робить код схожим на звичайні математичні вирази. Замість виклику методів на кшталт Merge() програміст використовує знак +. Це зменшує обсяг тексту та робить логіку програми зрозумілішою для інших розробників.



8\. Що нового ви дізналися під час виконання роботи? Я навчився працювати з індексаторами для швидкого пошуку студентів за номером залікової. Також опанував створення складних типів даних, як-от дроби зі скороченням, та зрозумів принципи взаємодії об’єктів через стандартні оператори.





Контрольні питання

1. Вимоги до сигнатури. Метод має бути відкритим статичним, містити ключове слово operator та приймати параметри того типу, де він

описаний.



2\. Оператор присвоєння. Його не можна змінювати, оскільки він зарезервований системою для керування копіюванням даних у пам’яті.



3\. Наслідки неповного перевантаження. Якщо перевантажити лише один оператор із пари порівняння, компілятор видасть помилку через порушення логічної цілісності.



4\. Призначення пар операторів. Вони необхідні для встановлення чіткого порядку між об’єктами, що дозволяє виконувати сортування та пошук мінімумів чи максимумів.



5\. Унарні та бінарні оператори. Унарні працюють з одним операндом, а бінарні потребують двох значень для виконання дії.



6\. Реалізація приведення. Використовується implicit для автоматичних перетворень та explicit для тих, що вимагають підтвердження від програміста.



7\. Доцільність використання. Оператори найкраще підходять для математичних та логічних дій. Для складних процесів із багатьма параметрами краще використовувати стандартні методи.
