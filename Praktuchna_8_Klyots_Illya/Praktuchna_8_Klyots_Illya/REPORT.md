1. Які класи використовуються для роботи з файловою системою в C#? Наведіть приклади.
Для роботи з файловою системою використовуються класи простору імен System.IO: статичні класи File та Directory для швидких операцій, FileInfo та DirectoryInfo для роботи з метаданими конкретних об’єктів, а також потокові класи StreamReader, StreamWriter, BinaryReader та BinaryWriter для послідовного читання та запису даних.

2. У чому різниця між File/FileInfo та Directory/DirectoryInfo?
Статичні класи File та Directory забезпечують швидкий доступ до базових операцій без створення екземплярів, тоді як класи FileInfo та DirectoryInfo створюють об’єкти, що кешують атрибути файлу чи папки, що значно оптимізує роботу при багаторазовому зверненні до одного й того ж ресурсу.

3. Поясніть роботу StreamReader та StreamWriter. Коли їх краще використовувати?
Це обгортки над потоками, які автоматизують керування кодуванням та буферизацію тексту. Їх доцільно використовувати для обробки великих файлів, які неможливо завантажити в оперативну пам'ять повністю, або для забезпечення поступового запису даних у лог-файли.

4. Як працює серіалізація об’єктів через System.Text.Json? Які атрибути ви використовували?
Серіалізація — це перетворення об’єкта в JSON-рядок через JsonSerializer.Serialize. У проекті я застосовував [JsonPropertyName] для відповідності формату CSV/JSON та [JsonIgnore] для виключення технічних даних (наприклад, допоміжних полів) зі збереженого файлу.

5. Які винятки можуть виникати при роботі з файлами? Як ви їх обробляли?
Помилки: FileNotFoundException, IOException, UnauthorizedAccessException та JsonException. Обробка реалізована через блоки try-catch, що забезпечує стабільність програми, а також через створення власного винятку InvalidFileFormatException для валідації структури даних.

6. Як ви реалізували резервне копіювання даних?
Резервне копіювання реалізовано методом CreateBackup класу FileManager, який використовує File.Copy для перенесення поточного стану бази даних у папку Backups з додаванням дати/часу до імені файлу, а метод CleanOldBackups видаляє застарілі архіви.

7. Які труднощі виникали під час роботи з файлами?
Основна проблема — відкриті файли, які не закривалися при помилках. Вирішив використанням блоку using, який автоматично звільняє ресурси.

8. Що нового ви дізналися під час виконання цієї практичної роботи?
Навчився керувати системними ресурсами через Навчився структурувати дані через JSON, керувати файловими ресурсами, створювати власні винятки та автоматизувати створення бекапів.

Контрольні питання
1.	Чим відрізняється File.WriteAllText() від використання StreamWriter?
WriteAllText записує весь файл одразу; StreamWriter пише поступово, заощаджуючи RAM.

2.	Що таке серіалізація та десеріалізація?
Серіалізація — запис об'єкта в файл; десеріалізація — зчитування з файлу в об'єкт.

3.	Навіщо потрібен using при роботі з потоками?
using гарантує закриття потоку навіть при помилках.

4.	Як обробляти помилки доступу до файлів?
Помилки доступу ловляться блоком try-catch.

5.	Що таке JsonSerializerOptions і для чого його налаштовувати?
JsonSerializerOptions налаштовує формат JSON (відступи, регістр).

6.	У чому небезпека роботи з відносними шляхами до файлів?
Відносні шляхи залежать від місця запуску програми, тому вони часто "гублять" файли.

7.	Коли краще використовувати бінарні файли, а коли текстові?
Текстові файли — для читання людиною, бінарні — для швидкості та економії місця.
